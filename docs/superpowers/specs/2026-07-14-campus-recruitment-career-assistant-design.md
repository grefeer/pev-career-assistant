## 1. 背景与现状

现有项目是一个 Vue、FastAPI、LangGraph 和 SQLite 组成的多智能体求职分析 Demo，已经具备用户登录、会话、简历文本解析、岗位分析、简历匹配、建议报告和 checkpoint 等基础能力。

现状与真实校招场景之间存在以下差距：

- 职位来自本地 `data/jobs.json`，属于演示数据，不是真实招聘职位。
- 简历主要以非结构化文本进入模型，尚未形成可校对、可复用的结构化人才档案。
- PDF 解析只提取文本，不支持 DOCX、字段证据、置信度和版本合并。
- AI 优化结果会覆盖当前简历文本，不适合要求事实可追溯的真实投递。
- 系统只能生成分析报告，不能在用户浏览器中辅助填写招聘表单。
- 当前 JSON 用户文件、SQLite checkpoint 和单体 API 适合演示，不适合多用户、后台任务和本地设备协同。
- 缺少管理员后台、真实职位核验、隐私分级、网站适配回归和安全动作门。

本需求将项目升级为服务真实校招求职场景的职位决策与辅助投递平台。

## 2. 产品定位

产品面向校招生，提供真实职位发现、职位核验、简历结构化、匹配分析、岗位定制简历和 GUI 辅助填表的一站式能力。

产品不是批量海投机器人，也不代替用户作出法律或求职承诺。系统负责发现信息、整理事实、提供建议和完成重复填表；用户负责确认个人事实、处理登录和验证码，并亲自完成最终提交。

### 2.1 核心价值

1. 将分散、质量不一的真实招聘线索转化为可验证、可搜索、可匹配的具体职位。
2. 将真实简历转化为可审查、可复用且不被 AI 擅自修改的结构化档案。
3. 用证据化匹配和岗位定制简历帮助学生做投递决策。
4. 在保证用户可见、可接管、可审查的前提下减少重复填写工作。
5. 通过禁止自动最终提交、敏感数据本地保存和完整审计降低误投与隐私风险。

## 3. 用户与权限

### 3.1 学生用户

学生用户可以：

- 浏览、筛选和收藏已核验职位。
- 手动添加职位链接或 JD 文本。
- 上传、校对和维护自己的结构化档案。
- 查看匹配报告并生成岗位定制简历草稿。
- 批准投递快照并对单个职位发起自动填写。
- 在本地浏览器中处理登录、验证码、审查和最终提交。
- 查看投递历史、执行异常和提交结果。
- 导出或删除自己的档案、附件、动态字段和投递记录。

### 3.2 平台管理员

管理员可以：

- 配置腾讯智能表数据源、目标子表、字段映射和同步频率。
- 查看同步日志、部分失败记录和字段结构变化。
- 审核图片型公众号文章和无法自动核验的招聘线索。
- 合并、拆分、修正、重新验证或下线职位。
- 维护网站适配配置、版本和远程熔断状态。
- 查看脱敏的网站级质量指标和异常统计。

管理员默认不能查看学生简历正文、普通档案明文、本地敏感字段或招聘网站页面内容。

## 4. 产品目标与非目标

### 4.1 MVP 目标

- 接入指定腾讯智能表并支持用户手动添加职位。
- 将招聘线索补全为具体职位、完整 JD 和有效投递入口。
- 支持 PDF、DOCX 和文本简历导入及在线结构化校对。
- 提供证据化匹配报告和需用户批准的岗位定制简历。
- 提供 Windows 本地执行器，在可见 Chrome 中完成单职位辅助填写。
- 支持单页、多页、用户接管、网站默认值、缺失字段、断线恢复和侧边栏审查。
- 确保系统在任何情况下都不会自动点击最终提交或语义不明的组合按钮。
- 核心网站达到生产严格级验收指标。

### 4.2 MVP 非目标

- 自动点击最终提交。
- 批量海投或高并发操作招聘网站。
- 云端托管招聘网站账号、密码或浏览器。
- macOS、移动端和多浏览器支持。
- 对任意招聘网站作无条件兼容承诺。
- 全网招聘爬虫、验证码绕过、反检测或设备指纹伪造。
- 求职导师、企业招聘方或学校就业管理角色。
- 公众号图片 OCR、二维码自动解析和扫码代投。

## 6. 端到端用户流程

1. 管理员同步腾讯智能表，系统保存原始记录并识别链接类型。
2. 系统自动补全官网或文本型招聘线索；图片型公众号文章进入人工审核。
3. 招聘线索被拆分、去重并核验为具体职位。
4. 学生上传简历，系统解析为结构化档案；学生校对并确认事实。
5. 学生选择职位查看匹配报告，并生成岗位定制简历草稿。
6. 学生审查差异并批准，系统生成不可变投递快照和附件。
7. 学生发起单职位填写任务，Web 平台确认本地执行器在线。
8. 本地执行器启动专用可见 Chrome 并打开具体职位入口。
9. 用户自行处理登录、扫码、短信验证、验证码和人机验证。
10. Agent 识别页面为单页、明确多页或无法确认，并按照安全策略填写。
11. 多页表单只点击已确认安全的中间保存或下一步；单页和末页直接进入审查。
12. 浏览器侧边栏汇总已确认、默认、缺失、低置信度和异常字段。
13. 用户修改并亲自点击招聘官网的最终提交按钮。
14. 本地执行器观察提交结果，并将任务记录为成功、失败或结果未知。

## 7. 功能需求

### 7.1 职位数据源与同步

#### JOB-001 数据源配置（P0）

管理员可以配置智能表链接、目标子表、启停状态、每日同步计划和手动立即同步。

验收标准：

- 能列出文档内子表并选择目标子表。
- 能读取字段定义、字段类型和全部分页记录。
- 每条记录保存来源文档、子表、记录 ID、同步时间和原始字段。
- 一个数据源失败不影响其他数据源。

#### JOB-002 增量同步与部分失败（P0）

同步任务必须支持增量、分页重试和部分成功，不得因中断覆盖上次成功数据。

验收标准：

- 失败信息包含数据源、分页位置、错误类型和重试入口。
- 部分读取时不能把未读取到的历史职位误判为失效。
- 表结构变化时暂停自动发布并通知管理员更新映射。

#### JOB-003 字段归一化（P0）

系统使用每个数据源独立的字段映射，将公司、招聘类型、岗位、地点、截止日期、内推码和投递链接归一化。未知字段必须保留在原始记录中。

#### JOB-004 用户手动添加（P0）

学生可以粘贴职位链接或 JD 文本。用户添加的职位默认仅本人可见，并进入与公共职位相同的补全和核验流程。管理员审核后可提升为公共职位，且不能暴露添加者身份。

### 7.2 职位补全、核验与管理

#### JOB-101 链接分类（P0）

系统将来源分类为招聘官网/ATS、文本型招聘文章、图片型公众号文章、扫码或邮箱人工投递、无法判断。

#### JOB-102 自动补全（P0）

对官网和可解析文本，系统追踪最终跳转，验证公司归属，提取具体职位、完整 JD、地点、批次、截止日期和最终投递入口。一条公司级线索可以拆分为多个具体职位。

#### JOB-103 图片型公众号文章人工审核（P0）

当公众号文章的主要招聘内容是图片时，MVP 不执行 OCR、不猜测官网，直接进入人工审核。

审核结果只能是：

1. 扫码、邮箱或其他人工直投：保留职位线索和人工投递指引，不启动 GUI Agent。
2. 存在招聘网站：审核人员录入网站或具体职位网址；Agent 验证网址可达、属于目标公司且存在招聘入口后，才能继续补全。
3. 无法判断：保持待核验，不进入可自动填写职位库。

系统保存原始智能表记录、公众号文章、人工录入网址、审核人、审核时间和验证结果。

#### JOB-104 去重与来源合并（P0）

系统根据公司、职位名称、地点、官网职位 ID/URL 和 JD 指纹联合去重。同一职位来自多个数据源时合并展示，并保留全部来源链。

#### JOB-105 职位状态（P0）

职位状态为：`待同步 → 待补全 → 待人工审核 → 已核验 → 已失效`；异常记录可进入 `已拒绝`。

只有 `已核验` 且存在具体职位和有效网页投递入口的职位可以启动 GUI Agent。

#### JOB-106 时效与快照（P0）

系统根据截止日期和官网状态下线职位。无明确截止日期的职位定期重新验证。已创建投递任务的职位即使之后失效，也必须保留创建任务时的不可变快照。

### 7.3 简历与结构化人才档案

#### PROFILE-001 简历导入（P0）

支持 PDF、DOCX 和文本粘贴。解析个人信息、教育、实习、项目、技能、获奖、证书、语言成绩和作品链接。

纯图片或无法可靠解析的简历保留原文件，并引导用户在线补充；简历 OCR 不属于一期核心能力。

#### PROFILE-002 字段证据与确认（P0）

每个解析字段保存原始证据、来源文件、置信度和用户确认状态。低置信度或冲突内容不得自动成为已确认事实。

#### PROFILE-003 档案合并与版本（P0）

重复上传不能直接覆盖主档案。系统生成差异，由用户选择新增、替换或忽略，并保留版本历史。

#### PROFILE-004 标准档案与动态字段（P0）

标准档案覆盖常见校招字段，并支持多段教育、实习、项目和获奖记录。网站特有问题保存为动态字段，包含标准语义、原始问题、答案、适用范围、敏感等级和确认时间。

用户可以指定动态答案仅适用于当前网站、当前职位或全局，并可以查看、修改、撤销或删除。

#### PROFILE-005 隐私分级（P0）

教育、项目和实习等普通档案在云端加密存储。身份证号、家庭成员、紧急联系人等敏感字段只保存在 Windows 本地加密保险库。云端只保存字段需求和不可逆引用，不读取敏感明文。

#### PROFILE-006 本地敏感字段编辑（P0）

本地执行器必须提供独立的敏感字段编辑和删除入口。Web 端只能显示某类敏感字段是否已配置及最后更新时间，不能展示、缓存或代填其明文。用户更换设备时，敏感字段默认不自动迁移，必须在新设备重新录入。

### 7.4 职位匹配与建议报告

#### MATCH-001 证据化匹配（P0）

系统先提取岗位硬性条件，再评估技能、经历、项目证据和求职偏好。匹配分数必须附带引用证据、缺口和不确定项。

缺失信息不能自动视为不满足条件。模型不得虚构经历、技能或成果。

#### MATCH-002 报告内容（P0）

报告包含职位真实性、匹配理由、硬性风险、优势、缺口、简历建议、投递优先级和不确定项。分析失败不影响用户查看职位或直接发起填表。

### 7.5 岗位定制简历与投递快照

#### RESUME-001 定制草稿（P0）

系统只能基于已确认事实调整排序、措辞、摘要和内容取舍。每处改动必须引用主档案事实，并以差异形式展示。

#### RESUME-002 用户批准（P0）

用户批准后生成不可变的投递快照和 PDF/DOCX 附件。自动填表和附件上传只能使用已批准快照。

用户修改已批准快照后必须重新确认；旧版本保留审计记录但不能继续用于新任务。

### 7.6 本地执行器与设备管理

#### LOCAL-001 设备配对（P0）

Windows 本地执行器通过一次性配对码绑定 Web 账号，使用可撤销、可过期和任务范围受限的设备令牌。用户可以在 Web 端解除设备绑定。

#### LOCAL-002 专用 Chrome（P0）

执行器启动可见的专用 Chrome 用户配置目录，与用户日常浏览数据隔离。招聘网站 Cookie 和登录状态只存在本地，系统不读取或上传密码。

#### LOCAL-003 人工接管（P0）

登录、扫码、短信验证、图形验证码和人机验证出现时立即暂停。只有用户点击“继续自动填写”，Agent 才能恢复。

#### LOCAL-004 本地保险库（P0）

敏感档案使用 Windows 系统级加密能力绑定当前用户。禁止使用明文文件、环境变量或普通未加密 SQLite 保存敏感值。

#### LOCAL-005 签名升级（P0）

本地执行器升级包必须签名，支持版本检查、灰度更新和安全回滚。过旧或已撤销版本不能领取新任务。

### 7.7 页面理解与字段填写

#### GUI-001 页面理解策略（P0）

页面理解优先级为：

1. DOM、标签、占位文字、无障碍树和页面结构。
2. 已知网站的版本化适配配置。
3. LLM 对未知字段的语义映射。
4. DOM 不足时的局部视觉回退。

视觉回退必须先遮罩敏感区域，不得上传整页敏感截图。用户可以关闭视觉回退。

#### GUI-002 支持的表单控件（P0）

支持文本框、单选、多选、下拉框、日期、级联地区、富文本、附件上传和可重复经历组件。

#### GUI-003 缺失字段与网站默认值（P0）

- 确定字段继续填写，不因普通缺失项中断。
- 网站已有默认值可以保留以继续流程，但必须记录为 `未确认默认值`。
- 缺失且非必填字段留空并记录。
- 必填字段没有网站默认值且确实阻塞下一页时，先完成当前页其他字段，再请求用户补充。
- 系统不得自行编造或随机选择网站未提供的默认答案。
- 所有缺失项、默认值和用户补充项必须在侧边栏和任务审计中上报。

#### GUI-004 填写回读（P0）

每次填写后重新读取页面值，确认组件未重置、格式化错误或选择失败。回读不一致时最多重试一次，仍失败则高亮并交给用户。

#### GUI-005 幂等填写（P0）

创建重复教育、实习、项目或获奖记录前，先检查页面现有内容。恢复任务时禁止重复添加已存在的经历。

### 7.8 页面拓扑与动作安全

#### SAFE-001 页面拓扑分类（P0）

进入填写页面后必须先分类为 `单页`、`明确多页` 或 `无法确认`。不能仅根据按钮文案或 URL 变化判断存在下一页。

#### SAFE-002 单页规则（P0）

单页表单填写完成后直接进入审查状态，不点击页面底部任何保存、确认、完成或提交按钮。

#### SAFE-003 多页规则（P0）

只有同时检测到明确后续步骤、步骤导航或下一分页，并确认按钮属于纯中间动作时，才能点击 `保存并下一步`。到达末页后停止并进入审查。

#### SAFE-004 永久禁止动作（P0）

`提交申请`、`确认投递`、`完成申请`、`保存并提交` 及其他最终或组合动作永远不得自动点击。语义不明确时按最高风险处理：不点击、保存现场、交给用户。

LLM 只能提出动作建议。独立的确定性安全门负责最终放行，且不能被提示词、重试或置信度调整绕过。

### 7.9 侧边审查与提交结果

#### REVIEW-001 浏览器侧边审查栏（P0）

侧边栏展示页面进度、已确认字段、网站默认值、缺失字段、低置信度映射和异常。点击问题可以跳回对应分页并高亮字段。

#### REVIEW-002 用户最终提交（P0）

最终提交按钮始终来自招聘官网，由用户亲自操作。执行器不模拟点击，也不提供自动提交快捷键。

#### REVIEW-003 提交结果识别（P0）

用户提交后，执行器观察成功页、URL、状态提示和错误信息，将结果记录为 `成功`、`失败` 或 `结果未知`。结果未知时不得自动再次提交。

## 8. 业务状态机

### 8.1 职位状态

`待同步 → 待补全 → 待人工审核 → 已核验 → 已失效`

异常分支为 `已拒绝`。扫码或邮箱直投可以作为已核验人工渠道展示，但不具备 GUI Agent 能力。

### 8.2 投递任务状态

| 状态 | 含义 |
| --- | --- |
| `CREATED` | 任务和投递快照已创建 |
| `PRECHECK` | 检查设备、Chrome、档案和任务一致性 |
| `NAVIGATING` | 打开招聘官网和具体职位 |
| `WAITING_HUMAN` | 等待登录、验证码、必填补充或用户接管 |
| `FILLING` | 填写当前页面 |
| `SAVING_PAGE` | 执行并验证安全的中间保存 |
| `REVIEW_REQUIRED` | 等待用户审查，Agent 不再主动推进 |
| `USER_SUBMITTING` | 用户正在执行最终提交，执行器只观察 |
| `SUCCEEDED` | 识别到提交成功 |
| `FAILED` | 识别到提交失败 |
| `UNKNOWN` | 无法判断提交结果 |
| `CANCELED` | 用户取消，禁止继续动作 |

### 8.3 页面动作决策表

| 页面类型 | 按钮类型 | Agent 行为 |
| --- | --- | --- |
| 单页 | 任意底部保存/确认/提交动作 | 禁止点击，进入审查 |
| 明确多页非末页 | 已验证的纯中间保存/下一步 | 允许点击并验证页面变化 |
| 明确多页末页 | 任意最终动作 | 禁止点击，进入审查 |
| 无法确认 | 任意可能产生副作用的动作 | 禁止点击，保存现场并进入审查 |
| 任意页面 | 保存并提交、完成申请等组合动作 | 永久禁止 |

## 9. 数据模型

### 9.1 核心实体

- `User`：学生或管理员账户。
- `Device`：已配对本地执行器、版本、状态和令牌信息。
- `JobSource`：腾讯智能表或用户手动来源配置。
- `RawJobRecord`：不可变原始记录和来源信息。
- `JobPosting`：归一化、可核验的具体职位。
- `JobSourceLink`：职位与多个来源、内推链接、官网链接之间的关系。
- `JobVerification`：自动或人工核验记录。
- `Profile`：用户主档案。
- `ProfileFieldEvidence`：字段原文证据、置信度和确认状态。
- `DynamicProfileField`：网站特有问题及适用范围。
- `ResumeAsset`：原始简历和生成附件的对象存储元数据。
- `ResumeVersion`：主档案或定制简历版本。
- `ApplicationSnapshot`：职位、档案、附件和字段答案的不可变投递快照。
- `ApplicationTask`：投递任务权威状态和当前页面进度。
- `ApplicationEvent`：脱敏执行、接管、安全门和结果事件。
- `SiteAdapter`：网站适配配置、版本、启停和质量指标。

### 9.2 数据权威性

- MySQL 保存用户、职位、档案、版本、投递任务和脱敏审计等权威业务数据。
- Redis 保存任务队列、设备短期在线状态、缓存、幂等锁和 LangGraph 分析检查点。
- 对象存储保存加密的原始简历、已批准附件和用户同意上传的脱敏诊断材料。
- 本地保险库保存敏感档案明文。
- 专用 Chrome 配置目录保存招聘网站 Cookie 和登录状态。

Redis 检查点丢失不能改变 MySQL 中的投递任务权威状态，也不能造成重复投递或绕过安全门。

## 10. 系统架构

### 10.1 Web 前端

Vue Web 工作台提供职位中心、档案编辑、匹配报告、定制简历审查、投递记录和设备管理。管理员后台提供数据源、核验队列、适配配置和脱敏质量指标。

### 10.2 FastAPI 应用服务

应用 API 负责认证、权限、用户档案、职位查询、投递快照、设备配对和实时任务状态。业务模块通过明确接口隔离，禁止继续扩展为单文件单体。

### 10.3 职位采集与核验服务

负责腾讯文档同步、字段归一化、链接分类、职位补全、去重、时效验证和人工审核队列。

### 10.4 档案与简历服务

负责文件解析、结构化档案、证据、版本合并、动态字段、定制草稿、差异审查和附件生成。

### 10.5 LangGraph 分析工作流

LangGraph 继续负责需要模型推理的职位要求提取、证据化匹配和建议报告。所有节点使用结构化输入输出。模型失败不能直接改变主档案或浏览器状态。

### 10.6 投递任务协调器

投递任务由确定性状态机协调，权威状态写入 MySQL。协调器向已配对设备下发脱敏任务并接收脱敏事件，不读取招聘网站凭据或本地敏感字段。

### 10.7 Windows 本地执行器

包含任务引擎、页面观察器、字段映射器、安全门、侧边审查栏、本地保险库、专用 Chrome 管理和签名升级模块。

### 10.8 通信边界

- 本地执行器通过出站加密长连接连接云端，服务器不能主动访问用户电脑。
- 云端下发任务 ID、职位网址、非敏感投递快照和字段需求。
- 本地执行器合并本地敏感值后填写浏览器。
- 本地只回传脱敏状态、字段类别、页面指纹和安全事件。
- 发送给 LLM 的 DOM 或截图必须最小化并脱敏。

## 11. 异常处理与恢复

### 11.1 异常分类

所有异常归入：自动重试、需要用户接管、需要管理员处理、永久安全阻断。用户界面必须显示失败位置、已完成内容和下一步操作。

### 11.2 数据源异常

- 只重试失败分页，不覆盖已成功数据。
- 字段结构变化时暂停自动发布。
- 链接失效、归属不明或图片型公众号文章进入待核验队列。
- 部分成功不能触发批量下线。

### 11.3 档案与模型异常

- 无文本、格式不支持或结构冲突时保留原文件并指明需补充模块。
- 结构化模型输出失败可重试一次，仍失败则保留已有结果并要求人工确认。
- 匹配失败不阻止用户直接填表。
- 定制简历失败时禁止创建投递快照，但不修改主档案。

### 11.4 本地执行器异常

- 执行器离线、版本过旧或 Chrome 启动失败时，任务保持待启动。
- 网络断开后保存本地现场；恢复时校验任务 ID、职位快照、URL 和页面指纹。
- 页面明显变化时不盲目续跑，重新识别或进入审查。
- 用户取消后不得再执行页面动作。

### 11.5 幂等与副作用控制

- 每完成一个分页，保存页面指纹、已填字段摘要、默认值、缺失项和安全动作。
- 网络请求和只读查询可以有限重试。
- 点击、添加经历和保存页面等有副作用动作，在结果不明时不得自动重复。
- 中间保存失败时停留当前页，不继续下一页。
- 网站结构变化触发单站适配熔断。

## 12. 安全、隐私与平台边界

### 12.1 身份与权限

- 学生和管理员使用独立权限模型。
- 管理员账号采用更强认证并记录配置操作。
- 设备令牌可撤销、可过期、限定用户和任务范围。
- 解除设备绑定后不能领取新任务。

### 12.2 数据保护

- Web、API 和本地执行器之间使用加密连接。
- MySQL、对象存储和备份中的个人数据加密并采用最小权限访问。
- 日志不得记录身份证号、手机号全文、家庭信息、Cookie、验证码和完整表单值。
- 必要截图默认保存在本地；上传诊断必须经用户同意并先脱敏。

### 12.3 LLM 数据最小化

- 字段匹配优先只发送字段名称和页面结构。
- DOM 片段和截图在发送前遮罩已有表单值和敏感区域。
- 模型供应商配置应禁止将业务数据用于训练，并采用尽可能短的数据保留周期。
- 用户关闭视觉回退后，无法识别的页面直接进入人工审查。

### 12.4 自动化边界

- 每个任务由用户主动发起，并限制在指定招聘域名。
- 执行器不得读取普通 Chrome 数据或扫描无关本地文件。
- 附件上传只允许使用已批准投递快照和用户明确选择的文件。
- 不绕过验证码、不破解反爬、不伪造设备指纹、不进行批量海投。
- 网站明确禁止自动化、出现账号风险提示或异常时立即停止。

## 13. 可观测性

- 使用统一关联 ID 串联云端任务、后台作业、本地执行器和浏览器事件。
- 记录同步耗时、职位补全率、待人工审核量、字段映射策略、填写回读结果、接管次数、安全门拒绝和任务结果。
- 质量面板只显示脱敏聚合指标。
- 适配配置按网站和版本监控错误率，超过阈值自动熔断。
- 原始敏感表单值、Cookie、验证码和密码不得进入监控系统。

## 14. 测试与验收

### 14.1 三层测试体系

1. 模拟页面：覆盖全部控件、页面拓扑、安全按钮、网络中断和恢复。
2. 历史页面回归：每次适配配置更新重放脱敏页面结构样本。
3. 真实网站验收：在授权账号和真实试点用户环境中验证核心网站。

### 14.2 核心网站样本

- 大疆、小鹏和科大讯飞每个网站至少 30 次完整任务。
- 核心测试覆盖不少于 10 份经过授权的测试档案。
- 小红书和汇川技术各至少 10 次 Beta 任务。
- 真实测试停在最终审查页，不为测试目的提交虚假申请。

### 14.3 发布指标

| 指标 | 门槛 |
| --- | --- |
| 已知字段填写正确率 | ≥98% |
| 符合自动化条件的任务到达审查状态比例 | ≥95% |
| 缺失字段与网站默认值上报率 | 100% |
| 暂停或断线后的恢复成功率 | ≥95% |
| 最终提交和歧义组合按钮自动点击次数 | 0 |
| 网站结构变化后的适配熔断率 | 100% |

指标口径固定如下：

- `已知字段填写正确率` = 经回读或人工审查确认正确的已知字段数 ÷ Agent 实际尝试填写的全部已知字段数。低置信度字段只要被 Agent 尝试填写，就必须计入分母。
- `到达审查状态比例` = 到达 `REVIEW_REQUIRED` 的任务数 ÷ 已进入受支持招聘网站填写页面的任务数。用户主动取消、招聘网站整体不可访问和账号被网站封禁可以排除；字段映射失败、页面改版、保存失败和执行器异常不能排除。
- `缺失字段与网站默认值上报率` = 被审查栏和审计事件同时记录的问题字段数 ÷ 人工复核发现的全部问题字段数。
- `恢复成功率` = 在同一职位快照和同一页面流程中成功恢复且未产生重复经历的任务数 ÷ 具备可恢复现场的暂停或断线任务数。
- `适配熔断率` 要求所有达到预设错误阈值的适配版本均自动停止领取新任务；已进入审查状态的任务不被远程恢复。

### 14.4 安全测试

- 验证学生、管理员和设备令牌越权均被拒绝。
- 检查 API、日志、模型提示和问题报告是否泄露敏感值。
- 验证设备解绑、本地保险库、专用 Chrome 和升级签名。
- 对最终提交同义词、组合按钮、图标按钮和单页底部按钮进行红队测试。

## 15. 灰度发布

1. 开发环境使用模拟页面持续回归。
2. 内部授权账号验证三个核心网站。
3. 5–10 名真实试点用户分批启用，每次只开放一个网站适配。
4. 核心指标达标后逐步扩大用户范围。
5. 新网站默认标记为 Beta。
6. 适配错误、隐私异常或安全门异常可以远程停用单站，不影响职位浏览和匹配。

## 18. 主要风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 招聘网站频繁改版 | DOM 优先、适配配置版本化、历史样本回归和单站熔断 |
| 98% 正确率难以达到 | 限制首期网站范围，低置信度进入审查，不强行填写 |
| 腾讯表格数据不完整 | 原始记录留存、自动补全、人工审核和来源链 |
| 小团队范围失控 | 第 8 周冻结 P0；Beta 网站不能影响核心验收 |
| 敏感数据泄露 | 本地保险库、最小化模型输入、日志脱敏和设备令牌隔离 |
| 自动化触发网站风险 | 用户可见操作、不绕过验证、限频、人工提交和单站停用 |
| 断线导致重复经历或重复提交 | 页面检查点、幂等回读、副作用不重试和 MySQL 权威状态 |

## 19. MVP 完成定义

MVP 只有同时满足以下条件才视为完成：

1. 两个腾讯智能表均可稳定同步，图片型公众号文章能够进入人工审核闭环。
2. 用户可以从 PDF/DOCX 建立并校对结构化档案。
3. 匹配报告和定制简历只引用已确认事实。
4. Web 平台与 Windows 本地执行器能完成设备配对和单职位任务。
5. 大疆、小鹏、科大讯飞通过真实网站验收门槛。
6. 单页不点击底部动作，多页只点击安全中间动作，最终提交自动点击为零。
7. 缺失字段和所有网站默认值均被标记并上报。
8. 登录、验证码、用户接管、断线恢复和结果未知均有明确状态与恢复路径。
9. 敏感档案明文不离开本地，日志和模型输入通过隐私测试。
10. 5–10 名真实试点用户完成灰度，未出现阻断级安全或隐私事故。

## 20. 后续实施工作包

本文件是整体产品需求与架构基线。由于项目包含多个独立子系统，开发前应按以下顺序为每个工作包形成独立实施规格和计划，不能用一个超大任务同时修改全部模块。

### 工作包 1：平台基础与权威数据

范围包括 MySQL 数据模型、Redis、对象存储、认证权限、设备实体、数据库迁移、审计事件和现有代码模块拆分。完成后，后续模块可以依赖稳定的实体和接口。

### 工作包 2：真实职位同步与核验

范围包括腾讯智能表连接器、原始记录、字段映射、补全、去重、图片公众号人工审核和管理员职位后台。

### 工作包 3：人才档案、匹配与投递快照

范围包括 PDF/DOCX 解析、标准档案、动态字段、本地敏感字段协议、证据化匹配、定制草稿和附件生成。

### 工作包 4：本地执行器与大疆纵向闭环

范围包括 Windows 安装与配对、专用 Chrome、本地保险库、页面理解、安全门、审查侧边栏、断点恢复和大疆 Moka 端到端验收。

### 工作包 5：多站适配与生产验收

范围包括小鹏、科大讯飞适配，小红书和汇川技术 Beta，回归样本、熔断、安全测试、灰度和发布指标验证。

每个工作包必须遵循本文件中的数据边界和安全不变量。工作包 4 未证明最终提交自动点击为零之前，不得开始扩大网站范围。
