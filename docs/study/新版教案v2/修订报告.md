## 当前关键事实边界

- API、Service、Repository 继续按 `routes → services → repositories` 分层；业务 SQL 不进入路由或服务。
- PEV Runtime 负责计划、执行、核验、预算、状态转换和恢复；DeepExecutor 位于 Executor 槽位，不是另一套外层编排器。
- 每个生产执行步骤恰好绑定一个 Skill；一个计划可以由多个单 Skill 步骤组成。
- MySQL 保存业务状态，MinIO 保存对象；主 PEV 事件流从 MySQL 按 sequence 轮询并通过 SSE 输出，Redis 不承担该主链通知。
- DeepSeek v4 的 thinking/json_mode 规则按模型名判断；所有模型 `temperature=0`，生产 Gateway 统一 `prefer_local_json_validation=False`。
- 登录、验证码和反爬阻断保持人工边界；默认不使用登录态继续抓取，也不参加自动恢复。
- Windows executor 保存最小恢复状态但不保存 token、lease、Cookie、验证码或完整表单值；提交动作必须经过人审。
- 评测中的 `RunMetrics.tool_calls` 是历史字段名：PEV 侧实为带 tool 的 Event 计数，可能漏计也可能多计，不能与 deepagents 预算计数作精确成本横比。
