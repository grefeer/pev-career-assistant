# 个人求职 Agent 面试教案 v2：从“看不懂术语”到“能讲清一次请求”

> v2 的核心改变：不把术语当成知识本身。每个词都先回答“它为什么叫这个名字”，再回答“它在代码里做什么”。

## 一、每章固定课堂节奏

1. **一分钟小剧场**：一个求职者、一个岗位、一个具体麻烦。
2. **老师暂停**：圈出本幕最多 3 个新词，做术语出生证。
3. **慢动作回放**：学生按“谁拿到什么、做了什么、写到哪里”复述。
4. **源码探险地图**：只打开一个主文件，告诉学生看哪几个函数，不让学生在仓库里迷路。
5. **故障演示**：如果模型撒谎、权限不够、页面被验证码拦截、进程断电，系统如何收场。
6. **学生抢答**：先让学生说错，再用代码证据纠正。
7. **面试压缩**：最后给 30 秒回答、3 个追问和一句记忆钩子。

## 二、20 个短章总路线

### A：先认识“这家小店”

01. **项目全景：从一句“帮我找工作”到四种交付物**——用一位求职者的一天解释产品、PEV、Skill、Tool、Harness、Run。
02. **两张地图：Web 分层和 Agent 分工不是一回事**——用“前台/经理/仓库”和“画图/干活/验收”对照 API→Service→Repository 与 PEV。
03. **简历上的话什么时候才算事实**——用“签字后的履历卡”解释 Profile version、confirmed facts、owner scope、私有事实。
04. **职位为什么要盖章才能给学生看**——用“线索、规范职位、审核盖章”解释 JobPosting、verified、review_version、PEV evidence、Artifact。

### B：把一次 Agent 请求拍成连续剧

05. **请求从门口到后台**——解释 AgentRun、queued、background task、SSE、waiting_user。
06. **Planner 不是聪明聊天员，而是出施工图的人**——解释 ExecutionPlan、PlanStep、acceptance criteria、Skill authority。
07. **Executor 像拿着工具箱的工人**——解释 decision、tool call、observation、duplicate call、stall breaker。
08. **Verifier 像拿着验收表的质检员**——解释 PASS、RETRY_EXECUTOR、REPLAN、NEED_USER、FAIL。
09. **预算和恢复像工地账本**——解释 turn/tool/replan/wall-clock、checkpoint、resume、recover、有界自动恢复（max_auto_recoveries=2、白名单、阶梯预算）、预算不复活。

### C：让工具和证据各就各位

10. **工具柜为什么有两把锁**——解释 ToolDefinition、allowed_roles、skill_name、catalog、invoke。
11. **证据不是“我看过”，而是可追溯的物证**——解释 source_url、content_hash、Artifact、bounded context projection。
12. **job-discovery 只进公开大厅**——解释公开 URL、重定向、Playwright、±25% 礼貌抖动、验证码/反爬人工门（默认不登录态抓取，allow_login_state_crawl 显式开启才放行）、JD 抽取。
13. **job-matching 是打分员，不是预言家**——解释观察 JD、确定性分数、未验证字段、模型负责解释而非改分。
14. **resume-tailoring 是编辑，不是编剧**——解释 confirmed facts、target evidence、diff、missing keywords。
15. **career-planning 是教练，申请记录与网页投递是另外两条轨道**——解释 JD 主题、完成条件，并说明 application tracking 不是当前四个 career Skill；登记基线和 Windows 投递状态机也不等于完整生产链已上线。

### D：把“能跑”讲成“能负责”

16. **六本账和三个储物柜**——解释 MySQL 主账、事件 sequence、Artifact 与 MinIO；当前主 PEV 持久化和 SSE 都不依赖 Redis。
17. **Model Gateway 是机场安检，不是模型本身**——解释通用/DeepSeek v4 参数、schema-first、有限 JSON retry、`model_request_failed` 与 `invalid_model_response`。
18. **前端不是黑屏等待，而是用户的控制台**——解释 Agent Workspace、Bearer SSE、sequence 游标、事件、产物、resume/recover；当前没有自动 gap 补读或自动重连。
19. **Windows Executor 必须把鼠标交还给人**——解释已有 ORM/协议/客户端/loopback 骨架，以及尚未闭合的生产设备与任务后端；READY 不是成功，UNKNOWN 不是重试信号。
20. **从测试清单到面试叙事**——区分默认 PEV、PEV 单 Step 内嵌 DeepExecutor、独立 deepagents 对照三层，并解释 `RunMetrics.tool_calls` 两腿口径不同且 PEV Event 计数可漏计或多计。

## 三、面试主线

面试时按四幅画讲：

1. **产品画**：确认用户事实 → 找公开岗位证据 → 匹配 → 简历建议 → 准备计划。
2. **运行时画**：Planner 画图 → Executor 拿工具取证 → Verifier 验收 → 成功、返工或请用户接管。
3. **工程画**：确定性 Harness 管权限、预算、证据、状态、恢复；MySQL 留主账。
4. **安全画**：不绕过反爬、不伪造事实、不自动最终提交；对照实验用数据决定是否换框架。

## 四、v2 学习验收

- 第一遍：只看每章小剧场和记忆钩子，能说出“谁在做什么”。
- 第二遍：只看术语出生证和源码地图，能从名词找到文件/函数。
- 第三遍：先做学生问题，再看答案；每章至少能说出一个失败路径。
- 面试前：完整讲第 01、05、09、16、20 章，形成 5 分钟和 30 分钟两个版本。
