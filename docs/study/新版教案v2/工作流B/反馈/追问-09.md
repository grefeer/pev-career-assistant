# 追问-09：第 09 章最终复核

## 结论

本章已把“可恢复事实”和“当前无法完整恢复的 DeepExecutor内部预算”分开，不再承诺数据库能还原全部内部动作。

## 我能复述的账本边界

一次生产 DeepExecutor生命周期只形成一个外层 PEV turn；内部物理模型调用以 `internal_model_calls` 汇总，内部工具调用不会逐个持久化为 `decision_json.action == "call_tool"`。运行中预算仍会约束这些调用，但 recover从数据库计数时无法完整补回未逐项持久化的内部消耗。计划 revision、外层 turns、事件和 Artifact仍是可恢复事实。

## 易错边界

- checkpoint是提交边界，不是完整内存快照。
- resume接 waiting_user；recover接进程中断的 running Run。
- 自动恢复默认最多两次，白名单含执行器握手码（route_already_consumed / candidate_urls_already_supplied / target_evidence_not_found / target_role_mismatch / target_source_mismatch）与 planner 层暂停（planner_needs_user / planner_budget_exhausted 事件）；登录、验证码、反爬、计划振荡和硬预算仍排除，不能创造访问权或复活硬预算。

## 30 秒回答

“恢复只信已提交事实。DeepExecutor内部调用没有逐项落成 turn，因此当前 recover不能完整还原内部工具预算；这是一条必须明说的实现边界。”
