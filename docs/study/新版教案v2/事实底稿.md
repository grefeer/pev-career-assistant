# v2 教案事实底稿

## 主线事实

- 主运行时是 `backend/app/services/agent_runtime/` 的自研 Planner–Executor–Verifier（PEV）运行时，不是生产 LangGraph。
- `backend/app/services/deepagents_runtime/` 是并行对照实现；旧 Supervisor/Web Navigation/worker job-discovery 链是退役历史。
- 四个当前职业 Skill：`job-discovery`、`job-matching`、`resume-tailoring`、`career-planning`。
- API → Service → Repository 是 Web/业务/数据访问分层；Planner → Executor → Verifier 是一次 Agent Run 内部的角色分层，两者不是替代关系。
- MySQL 是主 PEV 运行事实权威；主 PEV 持久化与 SSE 每秒轮询都不使用 Redis。MinIO 负责加密对象存储；独立 `deepagents_runtime/` 才有自己的 Redis checkpoint 语境。
- 证据必须由工具真实产出并带 `source_url`、`content_hash`；模型自报 URL 不是证据。
- 安全红线：不绕过登录、验证码、反爬；主 PEV 没有 `task:submit`；最终提交由人完成。
- “学生职位只允许 `verified`”是安全设计与 ORM/文档基线；当前尚无完整 JobPosting API→Service→Repository 学生查询链，不能把基线说成已交付接口。
- application tracking 不是当前四个 career Skill 之一；`ApplicationRecord*` 是登记基线，`ApplicationTask/ApplicationEvent` 与 Windows executor 是协议/骨架/模拟，runbook 所列完整设备与任务后端尚未闭合。
- Workspace 用带 Bearer 的 `fetch` + `ReadableStream` 读取 SSE；游标来自已读历史最后一项 `sequence`。当前没有显式 gap 检测、自动补缺或自动重连，流失败只报错，重新选择/刷新 Run 才重读历史。
- Model Gateway 对所有模型设 `temperature=0`，生产 Gateway 统一 `prefer_local_json_validation=False`；DeepSeek v4 才按模型名关闭 thinking 并使用 `json_mode`。本地 JSON 路径最多三次 provider invoke，若先有失败 structured invoke，`decide()` 最坏计四次；invoke 内部 HTTP 重试数不作绝对承诺。
- 评测需区分默认 PEV、PEV Step 内嵌 DeepExecutor、独立 deepagents 对照三层。PEV 的历史字段 `RunMetrics.tool_calls` 实为带 tool 的 Event 数，可能漏计也可能多计；独立腿读预算计数，两者不可精确横比。评测 `DEFAULT_BUDGET` 现为 36 turns / 64 tool calls / 2 replans / 600s 墙钟 / 256 模型请求 / 2M 输入 token / `max_auto_recoveries=2`；DeepExecutor 单次调用的内部模型上限为 20（`deep_executor.py`）。每题 record 自 2026-08 起含 `auto_recovery_count`（`run_auto_recovered` 事件数）。
- 有界自动恢复（auto recovery）是 Harness 自己 resume，区别于用户手动 resume 与进程故障 recover：`AgentBudget.max_auto_recoveries` 默认 2（上限 5），预算按 1.5x/2x 阶梯上调、连续 stall 阈值放 4/5（`context.max_consecutive_stalls`，上限 8）。白名单 10 个 reason code：`need_user`、`verification_failed`、`no_progress_duplicate`、`invalid_model_response`、`wall_clock_budget_exhausted`、`route_already_consumed`、`candidate_urls_already_supplied`、`target_evidence_not_found`、`target_role_mismatch`、`target_source_mismatch`；暂停契约取自最近一次 `run_needs_user` / `planner_needs_user` / `planner_budget_exhausted` 事件。登录/验证码/反爬（blocked=true）、重复计划振荡（repeated_plan_fingerprint）、硬预算耗尽（tool/model/replan budget）永不自动恢复。
- 公开浏览的礼貌节奏：`skill/job-discovery/scripts/browse.py` 全部人为等待在基准值 ±25% 随机浮动（下限 50ms）；登录态抓取默认关闭——观察到 `login_required`/`captcha`/`anti_bot_challenge` 后，`scripts/login.py`、`scripts/crawl.py` 被策略阻止，除非任务 context 显式 `allow_login_state_crawl=true`。
- 仓库 `skill/` 当前 canonical 包：`_common`（共享脚本）、`career-planning`、`job-discovery`、`job-matching`、`resume-tailoring`；已退役的 `application-tracking`、`company-research`、`interview-prep`、`output`、`tmp`、`conversation_history` 以 git mv 归档到 `skill_old/`，属保留非删除。

## 术语解释原则

- PEV：三个角色首字母，Planner=规划者，Executor=执行者，Verifier=验收者；不是第三方框架名称。
- Agent：在本项目中指会“观察 → 决策 → 调工具 → 看结果 → 调整”的 LLM 角色，不是所有 LLM 调用。
- Skill：围绕职业任务组织的 canonical Skill 包与运行时 `SkillDefinition`，可披露说明、资源和受控脚本；不是一个独立 LLM，也不只是工具列表。
- Tool：`ToolRegistry` 中确定性、固定输入输出的 Python 能力；模型选择调用时机，但不能改变工具权限和 schema。`run_skill_script` 是另一条受 Skill scope 与路径围栏约束的行动入口。
- Harness/runtime：主持流程、预算、状态、权限、持久化的宿主代码；它像裁判/舞台监督，不是另一个业务 Agent。
- AgentRun/Plan/Step/Turn/Event/Artifact：分别是一次任务、计划、计划步骤、一次角色决策、事件记录、证据/产物记录；每个名字都必须在章节中落到表或代码对象。
