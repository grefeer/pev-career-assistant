## 当前能力边界抽查

- application tracking 不是当前四个 career Skill，完整职位和申请后端链不能由 ORM 或 runbook 反推为已上线。
- 主 PEV/SSE 以 MySQL 为事实源，SSE 每秒直接轮询；Redis 不参与该链。
- Workspace 当前没有自动 gap 补读和自动重连。
- Windows Executor 是 ORM、协议、客户端、安全门与 loopback 骨架/模拟，完整生产设备/任务后端未闭合。
- 第 20 章已区分默认 PEV、单 Step 内嵌 DeepExecutor、独立 deepagents 对照；`tool_calls` 两腿口径不相同。

## v2 相比 v1 及本轮同步的实质变化

1. `PEV`、`Agent`、`Skill`、`Tool`、`Harness`、`AgentRun`、`Artifact` 不再只给英文名，而是逐个解释命名来源、代码落点和边界。
2. 每个故事都绑定“角色 → 输入 → 动作 → 落库/事件 → 下一步”，故事不再只是开场比喻。
3. 每章增加“把术语说错会怎样”的工程反例，例如把 Artifact 当成 JobPosting、把 Verifier 当成执行者、把 matching 分数当成录用概率。
4. 学生反馈专门检查注意力断点、突然出现的名词和失败路径复述。
5. 退役 Supervisor/Web Navigation/worker 只作为纠错背景；当前生产主线统一为 adaptive PEV 与四个 career Skill。
6. 文中把“当前实现”“设计契约”“骨架/模拟”“未来方向”分开，不再把 runbook、ORM 或 feature flag 当作完整上线证明。
