## 4. Concerns

- **Migration scope vs autogenerate output:** The migration was autogenerated with `--autogenerate` as required, but the raw output included ~80 lines of pre-existing schema-drift changes (altered columns, dropped/recreated foreign keys on unrelated tables like `application_snapshots`, `match_reports`, `resume_drafts`). These were trimmed to keep the migration focused on only the two new tables. If the intent was to use the raw autogenerated output verbatim, that would apply potentially destructive changes to existing tables — which violates the "Do NOT modify any existing models" constraint.

- **MySQL dependency for alembic:** `alembic --autogenerate` requires a live MySQL connection because the env.py calls `get_settings()` which needs `DATABASE_URL`. SQLite cannot be used as a drop-in because existing migrations contain MySQL-specific SQL. This means CI/CD pipelines will need a MySQL instance available for migration generation.

## 5. Fix applied

### Finding 1: test_url_pattern_indexed now uses Inspector

Previously, the test `test_url_pattern_indexed` only verified that a LIKE query on `url_pattern` returned the expected rows — which tests queryability but does **not** confirm an actual database index exists. An index could be missing and the query would still pass (just slowly).

Fix: Added an explicit index inspection block after the existing assertions, using `sqlalchemy.inspect()` (which returns a `sqlalchemy.engine.reflection.Inspector` instance) to retrieve indexes on the `job_discovery_strategies` table and assert that an index named `ix_job_discovery_strategies_pattern` exists.

Changed import: `from sqlalchemy import create_engine, text` → `from sqlalchemy import create_engine, inspect`.

### Finding 2: removed unused import `text`

The `text` function from `sqlalchemy` was imported on line 5 but never used anywhere in the test file. Removed it from the import statement.

Changed import: `from sqlalchemy import create_engine, text` → `from sqlalchemy import create_engine, inspect`.
